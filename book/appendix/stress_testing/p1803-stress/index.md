## 为什么需要练对拍

模拟赛 250 分左右的阶段，最常见的丢分原因不是「不会写」，而是：

> 我的贪心看起来是对的，但真的是对的吗？

**P1803 凌乱的 yyy / 线段覆盖** 是练这件事最合适的题：暴力、贪心、反例、随机数据，四样东西一次凑齐。

[[[p: luogu-P1803 | 凌乱的 yyy / 线段覆盖]]]

- 难度：普及−
- 建议练习时间：25～35 分钟
- 核心训练：随机数据生成 + 01 序列暴力 + 贪心 + 自动对拍

## 题目模型

给出 $n$ 场比赛的开始时间与结束时间，选出尽量多的**互不冲突**的比赛。

两个贪心候选，只差一个排序关键字：

| 策略 | 排序关键字 | 是否正确 |
|---|---|---|
| 早开始优先 | 按开始时间升序 | **错**（本文要让学生亲手证伪） |
| 早结束优先 | 按结束时间升序 | 对 |

## 四个文件搭一套对拍

在题目的工作目录里建好这四个文件（本文配套代码都在 `code/` 下）：

```text
p1803-stress/
├── gen.cpp           # 随机数据生成器
├── wrong_greedy.cpp  # 待验证的贪心（故意写错）
├── brute.cpp         # 标准答案：01 序列（二进制）枚举子集
└── check.sh          # 自动对拍脚本
```

## 1. gen.cpp：生成随机区间

```cpp file=./code/gen.cpp
```

::: warning
这里用 `rng() % (r-l+1)` 取随机数。它确实有理论上的取模偏差（模数不整除 $2^{32}$ 时），但 `mt19937` 的输出空间是 $2^{32}$，
区间长度又只有 10～20，偏差在 $10^{-9}$ 量级，对拍完全无感知。
真正要避开的是**两种老写法**：`rand()` 在很多平台上只有 32767 个取值、低位周期短；`srand(time(0))` 秒级种子会让两次运行拿到同一串数据。
追求严格均匀时再换 `uniform_int_distribution` 即可。
:::

::: info
生成器**不保证区间互不相同**（实测约 8% 的数据里会出现重复区间）。这不是 bug：两道完全相同的比赛拿来对拍，正好考一下冲突判断有没有写对。
:::

## 3. brute.cpp：标准答案，01 序列枚举

把「第 $i$ 场参加或不参加」看成一个 01 位，于是每一种方案就是一个长度为 $n$ 的 01 序列，
也就是一个二进制数 `mask`。枚举 `mask` 从 $0$ 到 $2^n-1$，逐位判合法即可。

```cpp file=./code/brute.cpp
```

这就是 [[[rbook: 01_seq]]] 和 [[[rbook: subset_enum]]] 里那套「选 / 不选」的直接落地：
不改题意、不加剪枝，只把所有可能性一个不漏地过一遍。

::: info
对拍时 $n \le 8$，最多枚举 $2^8 = 256$ 种方案，判合法最多再乘个 $8^2$，跑 1000 组也就一瞬间。
:::

::: warning
这份暴力必须**和题意同语义**：P1803 允许「上一场结束时间 = 下一场开始时间」首尾相接。
所以冲突判定要写成 `L[i] < R[j] && L[j] < R[i]`（相等不算冲突）。
写成 `<=` 就会把合法方案误判成冲突，标准答案变小——**对拍时先怀疑的应该是自己的暴力**。
:::

## 4. check.sh：对拍脚本

脚本就是 [[[rbook: compare_script]]] 里那套最小模板，一个字符都不多：

```bash file=./code/check.sh
```

循环体只有四句：生成数据 → 跑标准答案 → 跑被测程序 → `diff`；不一样就 `exit 1`。

把四个文件放在同一目录，在 NOI Linux 2.0 终端里执行：

```bash
chmod +x check.sh
./check.sh
```

| 行 | 作用 |
|---|---|
| `g++ ... \|\| exit 1` | 编译；失败就别拿旧程序去对拍 |
| `printf "\r$i"` | 原地刷进度，不刷屏 |
| `diff -b out_g out_std \|\| exit 1` | 答案不一致 → 找到反例，停下 |

`diff -b` 会忽略行尾空白和空行差异，避免因为多一个空格就假报错。
退出时 `in` / `out_std` / `out_g` 都留在目录里，供你直接 `cat` 看反例，不需要脚本帮你打印。

## 学生应该看到的结果

终止时，进度行后面接着就是 `diff` 给出的对比（`<` 是贪心，`>` 是标准答案）：

```text
7
1c1
< 1
---
> 2
```

接着自己看现场：

```bash
cat in        # 反例数据
cat out_g     # 贪心答案
cat out_std   # 暴力答案
```

（上面那组真实反例是 `7 / 11 13 / 3 18 / 3 9 / 3 12 / 12 13 / 12 18 / 1 20`：
贪心先选了最早开始的 `[1, 20]`，一选就把全场占满，后面全部作废，答案 `1`；
正确答案是 `[3, 9]` + `[11, 13]`，答案 `2`。）

手工构造也能得到同款反例，课堂上建议先给这一组：

```text
4
1 10
2 3
4 5
6 7
```

- 错误贪心输出 `1`：选中了 `[1, 10]` 这一场长比赛，之后全被挡住；
- 正确暴力输出 `3`：选 `[2, 3]`、`[4, 5]`、`[6, 7]` 三场短比赛。

::: colorfulbox
区间示意：橙色长条 `[1, 10]` 是错误贪心挑中的那场（一场占满全场）；绿色三条 `[2, 3]`、`[4, 5]`、`[6, 7]` 才是最优解。这一组数据精确说明了「开始得早」和「结束得早」不是同一件事。
:::

## 让学生自己修好贪心

要求只改 `wrong_greedy.cpp` 里的排序：把 `cmp_start` 换成 `cmp_end`，并换一下 `sort` 的第三个参数。

```cpp
// 正确策略: 结束时间最早的优先
bool cmp_end(int x, int y) {
    if (R[x] != R[y]) return R[x] < R[y];
    return L[x] < L[y];
}

// 主函数里改成:
sort(id, id + n, cmp_end);
```

再跑一次 `./check.sh`，1000 组应当全部通过。

为什么不变量是「结束时间」而不是「开始时间」？因为每选一场，唯一影响后续的是**这场比赛什么时候结束**：结束得越早，后面剩下的可选空间越大。这就是交换论证的核心——把最优解里的第一场换成当前结束最早的那场，不会让后面的选择变少。

## 对拍不能证明正确

::: warning
1000 组通过，只说明「没找到反例」，不等于「算法正确」。随机测试负责**发现错误**，数学证明负责**建立信心**，两件事不能互相替代。
:::

另外，标准答案本身也可能写错：如果把「首尾相接」误当成冲突，暴力算出来的答案会偏小，于是**贪心反而显得对**。所以对拍报错时，第一反应应该是回头核对自己的暴力和题意。

课堂上最后留三个问题：

1. 为什么暴力程序可以当标准答案？它必须满足什么条件？
2. 为什么生成器要故意生成小数据？如果 $n = 10^5$，还能用 $O(2^n)$ 的暴力对拍吗？
3. 对拍 1000 次没发现错误，能不能直接说算法一定正确？

参考答案要点：

1. 暴力必须**本身正确**且**足够慢但可跑**；标准答案一旦写错，对拍就是在比两个错误程序。
2. 小数据才能让暴力跑得起来，也才能让 1000 组覆盖更多结构；$n$ 很大时暴力跑不完，只能改成另一种（已证明正确的）算法互相对拍，或者放弃对拍、只做小数据验证。
3. 不能。反例可能极稀疏，随机数据也可能一直抽不到；随机对拍是工程手段，不是证明。
