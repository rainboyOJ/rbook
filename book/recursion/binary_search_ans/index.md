## 传统二分的思维痛点

在前面的《二分查找》中，我们学习了基于分界点判定的 `while (l < r)` 模板。但在实际做题和教学中，许多同学在面对复杂的最优化问题（二分答案）时，常常遇到以下困惑：

1. **边界死循环**：中点偏向与端点更新不对称（例如把 `l = mid` 和 `mid = (l+r)/2` 混用导致区间长度为 2 时死循环）；
2. **虚拟哨兵的负担**：为了处理无解情况，常常需要在序列末尾强行伪造一个无穷大元素（开到 $n+1$）；
3. **求最大值时思维割裂**：当问题变成“求满足条件的最大值”时，不得不去反向思考“找第一个不合法的”，二分出结果后再强行“减 1”；
4. **方案数据被抛弃**：二分判定（`check`）过程中明明已经找到了合法的方案参数（如最佳切分点、起点位置），但二分退出后只剩下一个数值，不得不重新写一次扫描来还原方案。

为了彻底消除这些心智负担，本篇介绍一种更加通用、自然、零边界陷阱的实现模式——**闭区间 `while (l <= r)` + 随手记账法**。

---

## 核心模型：闭区间搜索 + 随手记账

思考模型只有简单的两句话：
1. **搜索区间永远是真实的闭区间 $[l, r]$**：初始就是 $[1, n]$，不需要任何多余的哨兵；
2. **只要当前 $mid$ 合法，毫不犹豫立即“装进口袋记账”**（`ans = mid`）；接着根据贪心目标，将区间推向未知的更有希望侧！

具体执行逻辑如下：

1. **记账变量初值**：设置 `int ans = -1;`（或根据业务设定无解标记），代表“目前为止尚未发现任何合法解”；
2. **循环条件**：`while (l <= r)`，只要闭区间内还有未排查的元素就继续；
3. **检验中点**：取 $mid = (l + r) / 2$：
   - **若 $check(mid)$ 成立（当前可行）**：
     $mid$ 已经是一个有效的位置了！**立刻记账：`ans = mid;`**；
     - 若求最小值 / 最左解：更左边可能还有，贪心向左缩小范围：`r = mid - 1;`
     - 若求最大值 / 最右解：更右边可能还有，贪心向右扩大范围：`l = mid + 1;`
   - **若 $check(mid)$ 不成立（不可行）**：
     $mid$ 及其对应的一侧全军覆没，果断收缩搜索空间（`l = mid + 1` 或 `r = mid - 1`）；
4. **循环退出时**：搜索区间被完全排查完毕（$l > r$），**口袋里的 `ans` 必然是最优解**！若 `ans` 仍为 $-1$，说明全空间均无解。

## 经典应用场景

掌握了“随手记账二分法则”，所有二分问题都迎刃而解：

1. **基本查找问题**：
   - 第一个 $\geqslant x$ 的位置（求下界，合法时向左探 `r = mid - 1`）；
   - 最后一个 $\leqslant x$ 的位置（求上界，合法时向右探 `l = mid + 1`）；
   - 统计某个数 $x$ 的出现次数（上界下标 $-$ 下界下标 $+ 1$）。
2. **二分答案（最优化问题）**：
   - **求最大值（如“最多改 $k$ 个 0 的最长连续段”）**：可行时记账 `best = mid`，并贪心向右探寻更大解 `l = mid + 1`；
   - **求最小值（如“最大值最小的切分代价”）**：可行时记账 `best = mid`，并贪心向左试探更小解 `r = mid - 1`。
