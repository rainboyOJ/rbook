## 解DP的一般步骤

1. 仔细读题，明确输入、约束和所求目标。
2. 在纸上手动算出样例，确认自己理解了题意。
3. 判断是否适合用 DP：当问题能拆成结构相同的子问题，且后续决策只依赖子问题的当前结果（如最值、方案数）时，可以尝试 DP。
4. **确定目标并符号化**：把题目要求的结果写成状态，例如“前 $i$ 个数的最大和记为 $f[i]$”。
5. **分解原问题**：把当前状态拆成若干更小的子问题。
   - **小朋友法**：假设有“小朋友”已经帮你算出了更小规模子问题的答案，你只需要思考“拿回这些答案后，怎么拼出当前答案”。
   - **集合视角**：把状态看作一类方案的集合，按最后一步（或第一步）的决策将集合划分为互不重叠的子集。
6. **写出状态转移方程**：用数学式子表达“当前状态如何由子问题计算得到”。
7. **确定边界**：找出最小到无需再拆分的子问题，直接给出它们的初值。
8. **在纸上按方程填表**：用小数据手算一遍所有状态值，确认方程和边界没有漏情况。
9. 根据方程和边界编写代码。
10. 打印程序算出的状态表，与第 8 步手算的表逐项比对，排查实现错误。

设计 DP 时最常卡在两件事：**状态里该记哪些信息**，以及**转移怎么写才不重不漏**。下面两个方法分别解决这两个问题。

## 状态设计：非冲突法

::: note 设计状态时问自己
==试着给两个方案接上同一步，什么差别会让一个能接、另一个不能？== 找出这个差别，把它记进状态。
:::

DP 的本质是“丢掉过程细节，只保留最优值”，但如果丢掉了影响后续决策的信息，就会出错。

例如，从一排数中选若干个，相邻的数不能同时选。前两个数是 $3, 4$，如果只保留当前最大和 $4$，选 $3$ 的方案就被舍弃了。现在接上第三个数 $5$：选了 $4$ 就不能选 $5$，选了 $3$ 却可以继续选 $5$，得到 $3 + 5 = 8$。决定能否接上 $5$ 的关键信息，是**前一个数有没有选**。因此每算完一个位置，都要分别保留“末项选了”和“末项没选”两类方案的最大和。

用小朋友法下放问题时，也可以站在“接答案的人”这一边思考：先明确自己下一步要做什么，再决定请小朋友分别报哪些答案。如果两个方案面对同一种后续接法时，不仅**合法性相同**（都能接或都不能接），而且**增加的收益也相同**，那么它们对未来而言就没有区别，可以归入同一个状态，只保留当前较优的那个值。

## 状态设计：集合映射

::: note 先画方案，再写转移
==一个子问题圈定一个方案集合，状态值是对这个集合求出的答案。== 写转移时，先想清楚这个集合由哪些更小的方案集合拼接而成，再把拼接过程写成计算答案的式子。
:::

在 [[[rbook: number_pyramid]]] 中，给每个位置 $(i, j)$ 圈出一组方案：从 $(i, j)$ 出发、向下走到底层的所有路径。看着这组路径，就能定义对应的状态：记 $f[i][j]$ 为这组路径的最大路径和。

如果 $(i, j)$ 还没到底层，就按“第一步往哪走”把这组路径分成两类：
- 第一类：把 $(i, j)$ 接在从左下方 $(i+1, j)$ 出发的每条路径前面；
- 第二类：把 $(i, j)$ 接在从右下方 $(i+1, j+1)$ 出发的每条路径前面。

这两类合在一起，不重不漏地覆盖了从 $(i, j)$ 出发的所有路径。而且每条路径都只是多加上了当前格子的数值 $a[i][j]$，因此先分别取两类的最大值，再取较大者加上 $a[i][j]$ 即可：

$$f[i][j] = \max\bigl(f[i+1][j],\, f[i+1][j+1]\bigr) + a[i][j]$$
