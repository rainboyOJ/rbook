## 问题引入

前面几讲都在求「最大价值」。但同一张图、同一组物品，换一个问法就是新题目。这一讲收集几种常见的变形。

它们的共同点是：**状态转移方程基本不变，改的只是「合并」这一步怎么算**。

| 问法 | 改动 |
| --- | --- |
| 求最小价值 / 最少件数 | `max` 换成 `min` |
| 求方案总数 | `max` 换成累加 `+` |
| 求最优方案总数 | 记录方案数，与最优值同步更新 |
| 求第 $K$ 优解 | 每个状态存一个长度为 $K$ 的有序队列 |
| 输出具体方案 | 额外记录「这个值是从哪来的」 |

## 求方案总数

以完全背包为例，问「装满容量 $C$ 有多少种方案」。转移从取最大值改成累加：

$$
f(j)=\sum f(j-w_i)
$$

初始条件 $f(0)=1$——容量 $0$ 有一种方案，就是「什么都不装」。


::: note 为什么是累加而不是取最大
状态转移方程枚举了所有可能的构成方式。取最大只保留了其中最好的一个；累加则把每种方式都记下来。所以「求方案数」和「求最值」共用同一套状态设计，只差一个运算。
:::

## 求最优方案的总数

这里问的是：**达到最大价值的方案有几个**。

需要两个数组：$f(j)$ 存最大价值，$g(j)$ 存达到该价值的方案数。更新时两者同步：

- 若 $f(j)<f(j-w)+v$：最大价值被刷新，$g(j)$ 也跟着换成 $g(j-w)$；
- 若 $f(j)=f(j-w)+v$：多了一种达到同样最优价值的方式，$g(j)$ 累加。

## 求第 K 优解

把「取最大值」推广成「取前 $K$ 大」。

设 $f(j,k)$ 表示容量 $j$ 的第 $k$ 优解（$k$ 从 1 开始，1 最好）。转移时：

- 「不选第 $i$ 件」给出一个有序队列：$f(j,1),f(j,2),\dots$
- 「选第 $i$ 件」给出另一个有序队列：$f(j-w,1)+v,\,f(j-w,2)+v,\dots$

两者**归并**，取前 $K$ 个，就是新的 $f(j,\cdot)$。

::: warn 两个容易踩的坑
1. **负无穷会「变合法」**：无解状态用 $-\infty$ 表示，但 $-\infty+v$ 不再等于 $-\infty$。归并时必须先判断该位置是否有解，否则会凭空造出一个合法值。
2. **要不要去重**：题目若规定「价值相同但方案不同算同一个解」，归并时就要跳过与前一个相同的值；若算不同解，则不能去重。`kth_best.cpp` 按「去重」处理。
:::

复杂度从 $O(nC)$ 变成 $O(nCK)$——多乘一个 $K$。

## 输出具体方案

求最值时丢掉了「这个值是怎么来的」。要输出方案，就得把它记下来。

最直接的做法是再开一个数组 $g(i,j)$，记录 $f(i,j)$ 是取了两项中的哪一项。输出时从 $f(n,C)$ 倒着走：

```cpp
// g[i][j] = 0 表示没选第 i 件，1 表示选了
int i = n, j = C;
while (i > 0) {
    if (g[i][j] == 1) { print(i); j -= w[i]; }
    --i;
}
```

也可以不存 $g$，在回溯时**现算**：比较 $f(i,j)$ 与 $f(i-1,j)$ 是否相等，相等说明没选第 $i$ 件；否则就是选了。这样省掉一个数组。

::: note 字典序最小的方案
若要求输出「字典序最小」的最优方案，做法是把物品编号倒过来（$x\leftarrow n+1-x$）再跑标准 DP，输出时换回原编号。这样在「同样最优」时，程序会优先选择编号小的物品。
:::

## 小结

这一讲没有新算法，只有一组「换个运算」的观察：

- `max` → `min`：最小化类问题；
- `max` → `+`：方案计数；
- `max` → 有序队列归并：第 $K$ 优解；
- 额外记录来源：输出方案。

真正要提防的是细节：$-\infty$ 的传播、要不要去重、初始化怎么写。这些地方错了，程序照样跑，只是答案是错的。
