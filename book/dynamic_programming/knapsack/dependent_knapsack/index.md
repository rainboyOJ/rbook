## 问题引入

真实场景里，物品之间常有「要买 A 必须先买 B」的约束：

::: definition 有依赖的背包
有 $n$ 件物品和一个容量为 $C$ 的背包。每件物品有重量 $w_i$、价值 $v_i$，以及一个依赖 $p_i$：
$p_i=0$ 表示它不依赖任何物品（称**主件**），$p_i>0$ 表示**选了它就必须选 $p_i$**。
依赖关系保证无环，每件物品最多依赖一件。求最大价值。
:::

## 先看简化版：主件 + 至多两个附件

这就是 NOIP2006「金明的预算方案」的模型。每个主件最多带两个附件，且附件不再有附件。

一个主件和它的附件，可能的买法只有几种：

1. 都不买；
2. 只买主件；
3. 主件 + 附件 1；
4. 主件 + 附件 2；
5. 主件 + 两个附件。

这五种买法**互斥**（你只能选一种），所以「一个主件及其附件」恰好是一个**物品组**——正是分组背包的模型。把每种买法算成一个「物品」，组内至多选一个，用分组背包求解：

```cpp file=./code/main_attach.cpp
```

样例输出：

```plaintext

```

::: warn 这个写法的前提
`main_attach.cpp` 假设每个主件最多两个附件、且附件没有自己的附件。如果数据不满足这个前提（比如附件还带附件），它会给出错误答案。放宽这个限制要用下面的树形 DP。
:::

## 一般情形：依赖是一棵森林

去掉「最多两个附件」的限制后，依赖关系就是一片森林：主件是根，附件是它的儿子，附件还能有附件。

加一个虚拟根 $0$，把所有主件挂在它下面，森林就变成一棵树。**选了儿子就必须选父亲**，于是可以自底向上 DP：

设 $f(u,j)$ 表示「以 $u$ 为根的子树里，**包含 $u$**、总花费为 $j$ 时的最大价值」。

对每个点 $u$：

1. 先把 $u$ 自己放进去：$j\ge w_u$ 时 $f(u,j)=v_u$，否则无解；
2. 再依次把每个儿子 $son$ 的 DP 数组合并进来。合并时枚举「分给已合并部分多少容量」：

$$
f(u,j)=\max_{0\le k\le j}\Bigl\{\,f(u,\,j-k)+f(son,\,k)\,\Bigr\}
$$

3. 合并完所有儿子后，$f(u,\cdot)$ 就是 $u$ 这棵子树的答案。

由于 $f(u,\cdot)$ 强制包含 $u$，「包含儿子就包含父亲」自动成立。

```cpp file=./code/tree_dp.cpp
```

样例输出：

```plaintext
17
```

::: note 为什么合并时容量要倒序
合并儿子时，$f(u,j-k)$ 必须还是「没合并这个儿子」的旧值。若正序枚举 $j$，同一个儿子可能被重复计入。这与 01 背包倒序是同一个道理。
:::

## 和「泛化物品」的联系

把 $f(u,\cdot)$ 看成一个数组，它就是一个函数：**给它分配费用 $j$，能得到价值 $f(u,j)$**。

这正是下一讲要讲的「泛化物品」。依赖关系树的每一棵子树都等价于一件泛化物品，求某个点对应的泛化物品，就等于把所有儿子的泛化物品加上自己，再求和。

所以树形 DP 的合并操作，本质上就是「泛化物品之和」的运算：

$$
f(u,j)=\max_{0\le k\le j}\bigl\{h(k)+l(j-k)\bigr\}
$$

## 小结

有依赖的背包有两个层次：

- **浅层**：主件 + 少量附件的固定组合 → 枚举所有互斥买法 → 变成物品组 → 分组背包。
- **深层**：任意深度的依赖森林 → 加虚拟根 → 树形 DP，儿子合并进父亲，强制选父亲。

两种做法的共同点是**把互斥的选择打包成一个「物品」**。区别只是打包的方式：简化版手工枚举，一般版用 DP 算出来。
