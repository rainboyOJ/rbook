# 写作口味

用简明的教材正文讲清问题。保留必要推理，删去不推进理解的文字。
用户对当前文章的明确要求优先于本技能。

## 标题

- 直接点明主题，优先用简短的名词或短语。
- 解释、提问和教学引导放在正文，不堆入标题。
- 同类小节统一命名，例如“状态定义”“转移方程”“代码实现”。
- 不限定字数，不为缩短而删掉区分概念所需的信息。

| 冗长写法 | 推荐写法 |
|---|---|
| 状态机 DP：从选与不选到有限阶段流转 | 状态机DP |
| 从连续段 DP 再往前走一步 | 连续段DP进一步 |
| 第一台阶：选与不选，把不同的未来分开 | 选与不选 |
| 为什么三个阶段足够？ | 正确性证明 |
| 初始化和答案，不能凭感觉写 | 初值与答案 |

## 语言

- 直入问题，每段围绕一个要点，句子尽量短。
- 使用平实、准确的陈述，不写热场、口号、感叹和夸张评价。
- 必要术语保留，先交代含义，再使用符号；不堆砌抽象名词。
- 正文可保留推进推理的提问，但不连续设问，不把每段都写成问答。
- 不重复前文结论，不强加总结，不用多种比喻反复解释同一件事。

| 避免 | 推荐 |
|---|---|
| 贪心彻底失效！ | 这个反例说明，该贪心策略不成立。 |
| 空间复杂度达到惊人的 O(1) | 只保存上一层状态，额外空间为 O(1)。 |
| 掌握这个武器，就能秒杀一类题 | 说明它适用的条件，删去效果承诺。 |

## 讲解与详略

- 需要推导时，从具体困难引出关键观察，再说明状态或模型，最后给出公式和代码。
  简单内容直接讲，不给每篇文章强套完整结构。
- 把篇幅留给真正的卡点。例如 DP 应解释为何保留这些历史、同状态为何能取最优、转移是否遗漏。
- 解释到足以理解和验证为止。常规操作简写，代码不逐行复述。
- 影响当前解法正确性的初值、边界、答案范围和复杂度留在正文。
  次要变体、扩展讨论可放入折叠框，不把主线所需的推理藏起来。
- 例子用于澄清概念或检验结论。反例需真正推翻所述策略，不能只凭叙述宣称成立。
- 精简不改变事实、适用条件、公式和代码语义。不把有条件的结论改成绝对判断。

## 修改范围与格式

修改已有文章时，只调整用户任务涉及的部分。仅要求精简标题时，不顺带重写正文。

本技能管表达；本仓库 Markdown 语法、元数据和渲染规则由
[rbook-markdown](../rbook-markdown/SKILL.md) 管理。编辑 `book/` 下的 Markdown
或 `book/catalog.yaml` 时，仍须遵守该技能，不在这里重复方言说明。
