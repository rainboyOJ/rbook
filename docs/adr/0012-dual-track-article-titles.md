# 文章标题双轨：菜单短名与正文长名

菜单栏窄、正文标题可以长，这两个需求不是同一个字段能同时满足的，所以承认一篇文章允许有两个名字，各自有唯一的住处：

- 正文标题 front matter 的 `title`（可长）——页面 `<title>`、正文 H1、`dist/catalog.json` 都用它，取值链 `title → catalog.yaml title`。
- 菜单短名 front matter 的 `menu_title`（可选，要短）——侧边栏用它，取值链 `menu_title → catalog.yaml title`；没写就沿用 `catalog.yaml` 里的名字，存量文章因此不需要迁移。目录节点没有文章，只有 `catalog.yaml` 的 `title`。

不新增 `short` 字段，文章 `id` 保持稳定。侧边栏搜索只匹配菜单中实际显示的标题、`search_aliases` 与文章 `id`；面包屑只作为结果的路径说明，正文长标题不再进入搜索索引。

搜索别名在 `book/catalog.yaml` 的条目上配置，例如 `search_aliases: [线段树, sgt, segtree]`。目录的别名由所有后代叶子继承，文章自己的别名会与继承值合并；忽略大小写，去重。目录标题不会自动成为别名，要让整个主题可按中文名称搜索，应把中文名称也列入该目录的别名。

关键词完整命中已配置的别名时，只做精确、前缀和包含匹配，排除跳字及编辑距离结果。例如 `bit` 明确指向树状数组，不会因为 `binary_tree` 按顺序包含 b/i/t 就把二叉树也列出来；输入 `bti` 等未命中的词时仍可启用容错。

匹配按精确、前缀、包含、按顺序跳字、拼写容错分级排序。同级结果保持目录顺序，多关键词必须同时满足，可以分别命中不同字段。1–2 个英文字母只匹配完整词或词前缀，中文仍支持包含和跳字；英文关键词至少 3 个字符才启用编辑距离，允许一次插入、删除、替换或相邻交换，查询与候选单词都至少 7 个字符时允许两次编辑。容错针对完整英文单词和 id，不做中文拼音推断。

代价与守卫：两轨并存意味着同一个页面会同时出现短名与长名，这是预期行为而不是 bug；为了防止短名把菜单撑爆，`menu_title` 显示宽度超过 32（约 16 个汉字）时 `npm run check:catalog` 报 warning，存量 `catalog.yaml` 里的旧名字不在校验范围内。

这两轨都在文章自己的 front matter 里（元数据随后迁入 md，见 0013），因此「目录 config 作用到兄弟文件」的问题从结构上消失。

这份决定取代 0012 早先「菜单与正文必须同名」的版本，并修正 0002 里「catalog 承担导航显示名」的部分。
